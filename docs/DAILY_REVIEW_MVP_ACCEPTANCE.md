# Daily private review MVP acceptance

This is a local verification receipt, not production enablement or delivery proof.
No human approval or public publication is generated by this runner.

## Test strategy

- Fresh-schema integration: apply every tracked SQL migration to an empty local
  PostgreSQL cluster and check the new outbox/RPC effective ACL.
- Behavioral integration: separate synthetic-only database using the existing
  review fixture, exact-version reconcile, deduplication, eight concurrent
  claims, eight concurrent send-start calls, and a process restart after unknown
  delivery. A new claim token must not recover or retry an unknown delivery.
- Negative behavior: stale sources excluded; no approval/publication rows.
- CLI safety: explicit sole `--local-only` argument required; no URL or existing
  database input; environment credentials not inherited; Unix socket only.

## Run

From the repository root with local Homebrew PostgreSQL 16 and Node installed:

```sh
node scripts/verify_daily_review_mvp_local.mjs --local-only
python -m pytest tests/test_daily_review_mvp_harness.py -q
```

The runner starts its own random disposable cluster, disables TCP listening,
and stops/removes only that cluster on completion. It makes no provider calls.
Failures print phase labels, not copy, credentials, SQL error payloads or URLs.

## Scope limitations

Fresh full migrations establish local migration compatibility, not hosted
PostgreSQL version, permissions, owner configuration or production schema proof.
Behavioral fixtures are intentionally separate from the full production schema.
No Telegram message, image byte readback, live Studio authentication, or hosted
end-to-end delivery is established here. Those remain separately authorized
canary acceptance steps, with public publishing disabled.
